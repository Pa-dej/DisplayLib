# Частицы (`particles/*.jmc`)

Частицы из Display-сущностей: цветные квадраты и текст со спрайтами (`TextDisplay`), предметы (`ItemDisplay`), блоки (`BlockDisplay`).
Каждая частица - отдельная сущность, но сервер не двигает её каждый тик: он просчитывает движение вперёд
отрезками и отправляет цель - позицию, размер, поворот, цвет, - а плавность между кадрами рисует клиент.
Длину отрезка сервер выбирает по траектории: там, где скорость быстро меняется (старт, вершина дуги, отскок),
кадры чаще, на ровном полёте - реже, но не реже раза в `keyframeTicks` тиков. Поэтому десятки и сотни
частиц почти ничего не стоят серверу и сети. Клиент показывает частицу с задержкой в один тик.

Эффект - файл `plugins/DisplayLib/particles/<id>.jmc` (вложенные папки тоже читаются). Примеры выгружает
`/displaylib examples`, перечитывает `/displaylib reload`.

```java
// particles/confetti.jmc
String id = "confetti";              // по умолчанию - имя файла
String viewers = "all";              // "all" - видят все; "owner" - только игрок, для которого запущен эффект
int keyframeTicks = 4;               // 1..59: самый длинный кадр; меньше - точнее траектория, больше пакетов

dyn render = {
    type: "TEXT",                    // TEXT, PIXEL, ITEM, BLOCK
    variants: ["█", "▌", "▬"],       // случайный вариант на частицу; text: "★" - один
    colors: ["#ff595e", "#ffca3a", [138, 201, 38]],
    billboard: "CENTER",             // CENTER (лицом к игроку), FIXED, VERTICAL, HORIZONTAL
    brightness: 15,                  // 0..15, светится независимо от освещения
};

dyn emitter = { shape: "POINT", count: 40 };

dyn motion = {
    lifetime: [100, 160],            // тики
    speed: [0.2, 0.38],              // блоков за тик
    direction: [0, 1, 0],            // ось разлёта или "OUTWARD" - от центра формы
    spread: 45,                      // половина угла конуса вокруг оси; 180 - во все стороны
    gravity: 0.018,                  // блоков/тик²; отрицательная - всплывает
    drag: 0.04,                      // доля скорости, теряемая за тик
    collide: true,                   // удары о блоки
    bounce: 0.35,                    // доля скорости после удара; 0 - сразу останавливается
    friction: 0.5,                   // доля скорости вдоль поверхности после удара
    // attract: 0.02, attractAxis: "Y", wander: 0.02 - см. ниже
};

dyn animation = {
    scale: [0.25, 0.4],              // начальный размер
    endScale: 0,                     // размер к концу жизни, доля начального (1 - не меняется)
    easing: "EASE_IN",               // LINEAR, EASE_IN, EASE_OUT, EASE_IN_OUT, BOUNCE, ELASTIC
    fadeIn: 0,                       // за сколько тиков вырасти из нуля
    rotation: [0, 360],              // начальный угол в плоскости частицы
    spin: [-20, 20],                 // градусов за тик
    // color: [[0, "#ffffff"], [0.5, "#ff8800"], [1, "#00000000"]] - цвет по доле жизни
    // opacity: [1, 0]                                             - непрозрачность по доле жизни
};
```

Любое число можно задать диапазоном `[min, max]` - значение выбирается случайно для каждой частицы.

## `render` - что рисует частица

| Тип | Поля |
|---|---|
| `TEXT` | `text` - один текст, `variants` - список вариантов. Текст форматируется как у виджетов: строка или `[ { text, color }, { sprite, atlas, color }, { player, hat } ]` - значит, частицей может быть спрайт или голова игрока. `colors` / `color` - случайный цвет на частицу. `shadow`, `background: [r, g, b]` + `backgroundAlpha` (по умолчанию фона нет). |
| `PIXEL` | Цветной квадрат: фон пустого текста, растянутый в квадрат (приём из [text-display-experiments](https://github.com/TheCymaera/minecraft-text-display-experiments)). Любой цвет и прозрачность, цвет меняется плавно. `colors` / `color` - случайный цвет на частицу (по умолчанию белый). Лучший тип для огня, воды, искр и светлячков. |
| `ITEM` | `item: "GOLD_NUGGET"` или `items: [...]` - случайный предмет. `glow: true` - контур свечения (виден сквозь блоки), `glowColor: "#33ff66"` - его цвет (по умолчанию белый). |
| `BLOCK` | `block: "minecraft:glowstone"` или `blocks: [...]`, можно с состоянием: `"oak_log[axis=x]"`. `glow`, `glowColor` - как у `ITEM`. По умолчанию `billboard: "FIXED"`. |

Общие: `billboard`, `brightness`. Размер и поворот частицы считаются вокруг центра картинки.

Цвета: `"#rrggbb"`, `"#rrggbbaa"` (с прозрачностью), имя (`"red"`), `[r, g, b]`, `[r, g, b, a]`.

### Кадры текста

Любой вариант текста (и `text`) может быть анимацией кадров - как `frames` у текстовых кнопок экранов: вместо
текста пишется таблица с кадрами. Статичные и анимированные варианты смешиваются, на частицу берётся случайный.

```java
dyn render = {
    type: "TEXT",
    variants: [
        "★",                                                 // статичный
        { frames: ["◐", "◓", "◑", "◒"], frameInterval: 3 },  // кадры по кругу, 3 тика на кадр (по умолчанию 4)
        { frames: ["·", "✦", "✧", "·"], framesOverLife: true, frameStart: "random" },
    ],
};
```

- `frameInterval` - тиков на кадр, по кругу; `framesOverLife: true` - вместо круга один проход за жизнь: первый кадр
  при рождении, последний к смерти (как частицы Minecraft); `frameStart: "random"` - каждая частица со случайного кадра.
- Кадр - строка или сегменты (спрайты, головы, цвета). Пример `smoke`: `text: { frames: [ [{ sprite: "generic_7",
  atlas: "minecraft:particles" }], … ], framesOverLife: true }` - кадры ванильного дыма. Цвет из `colors` /
  `animation.color` тонирует и спрайты.
- Краткая запись одного анимированного варианта: `frames`, `frameInterval`, … прямо в `render`.
- Смена кадра - один пакет метаданных каждому игроку: маленький `frameInterval` у сотен частиц заметно добавляет
  трафика. Кадры лучше делать одного размера (центр частицы считается по первому кадру).

## `emitter` - откуда и сколько

| Поле | |
|---|---|
| `shape` | `POINT`, `SPHERE` (`radius`), `CIRCLE` (горизонтальный, `radius`), `BOX` (`size: [x, y, z]` - полные размеры) |
| `surface` | `true` - только по поверхности сферы / контуру круга / граням коробки |
| `count` | частиц сразу при запуске (по умолчанию 1, при `duration` - 0) |
| `duration`, `rate` | испускать `rate` частиц за тик в течение `duration` тиков; дробный `rate` копится (`0.5` - частица раз в 2 тика). `duration: -1` - пока запуск не остановят (`stop()`, `/displaylib particle stop`) |

## `motion` - движение

Без `collide` траектория считается без мира: частицы проходят сквозь блоки, зато не нагружают сервер.
С `collide: true` сервер проверяет блоки на пути (только в загруженных чанках): частица отражается от
стен и пола с потерей скорости (`bounce`), скользит с трением (`friction`) и ложится, когда почти остановилась.
Частица, родившаяся внутри блока, летит без коллизий. При ударе частица прижимается к грани блока; клиент ведёт её
между кадрами по прямой; у удара кадры сами становятся короче, так что отскок не «срезается».

Силы (траектория по-прежнему считается сервером наперёд, кадры не учащаются):

| Поле | |
|---|---|
| `attract` | притяжение к точке запуска, блоков/тик² (отрицательное - отталкивание); вблизи центра ослабевает, чтобы частица не дрожала |
| `attractAxis: "Y"` | притягивать к вертикальной оси через точку запуска - пламя стягивается к «фитилю», высота не мешает |
| `wander` | блуждание, блоков/тик²: толчок вдоль направления, которое каждый тик немного поворачивается - плавный «живой» путь (светлячки) |

## `animation` - вид во времени

| Поле | |
|---|---|
| `scale`, `endScale`, `easing`, `fadeIn` | размер: начальный, к концу жизни (доля начального), кривая, вырастание из нуля. `LINEAR` (по умолчанию) клиент ведёт сам - один пакет на всю жизнь; другие кривые сервер разбивает на кадры, это дороже |
| `rotation`, `spin` | начальный угол и скорость вращения в плоскости частицы, градусы и градусы за тик |
| `color` | цвет по доле жизни (вместо `render.colors`): `["#ffffff", "#ff8800", "#00000000"]` - равномерно, `[[0, "#ffffff"], [0.2, "#fcd303"], [1, "#00000000"]]` - с долями. Смешивание в OkLab - без грязно-серой середины |
| `opacity` | множитель непрозрачности по доле жизни: `[1, 0]` - тает, `[[0, 0], [0.15, 1], [0.85, 1], [1, 0]]` - появляется и гаснет. Третий элемент точки - изгиб отрезка, который к ней приходит (кривая Безье): `[1, 0, [0.5, 0.25]]` - кривая проходит через середину отрезка на 0.25 выше прямой; первое число - где на отрезке узел (0.25..0.75) |

Цвет и прозрачность у `PIXEL` и прозрачность текста у `TEXT` клиент интерполирует так же плавно, как размер и поворот.
Цвет текста (`TEXT`) меняется ступенькой на каждом кадре. У `ITEM` и `BLOCK` цвета нет.

## Запуск

```
/displaylib particle <effect> [x y z] [player] [count]
/displaylib particle list            эффекты и сколько частиц живо
/displaylib particle stop            убрать все частицы
/displaylib particle shatter <текст> слово перед игроком рассыпается на буквы (эффект letters, &-коды цвета)
```

Координаты поддерживают `~` (от игрока или командного блока); без координат - в 2.5 блоках перед игроком.
`player` - для кого эффект: при `viewers = "owner"` частицы видит только он (по умолчанию - тот, кто вызвал команду).
`count` - другое число частиц во всплеске.

Java API для других плагинов:

```java
ParticleEmission e = Particles.play("confetti", location);          // видят все
Particles.play("poison", location, player);                          // для viewers = "owner" - только этот игрок
Particles.play(Particles.effect("sparkle").withCount(60), location, null);
e.setCenter(newLocation);   // сдвинуть точку испускания (для эффектов с duration)
e.stop();                   // перестать испускать, выпущенные доживают
e.cancel();                 // убрать всё сразу
Particles.stopAll();
```

### Свои частицы: слово рассыпается на буквы

Частицы можно задать явно - где каждая появляется и что показывает, а движение и анимацию взять из эффекта.
На этом построен `TextShatter`: слово висит обычным `TextDisplay`, через `hold` тиков исчезает, и на месте
каждой буквы появляется частица с этой буквой (со стилем слова), дальше она летит по эффекту.

```java
TextShatter.Handle h = Particles.shatter("слово")   // или Component со цветами/жирностью
        .at(location)          // низ текста по центру, как у TextDisplay
        .facing(player)        // текст повёрнут к игроку (или .yaw(градусы))
        .effect("letters")     // как летят буквы: particles/letters.jmc (по умолчанию)
        .hold(20)              // секунду висит целым
        .scale(1.5)
        .owner(player)         // для viewers = "owner"
        .play();
h.cancel();                    // убрать слово или уже разлетевшиеся буквы

// то же вручную: любые частицы с любым текстом в любых точках
Particles.playPieces(Particles.effect("letters"), center, null, List.of(
        new ParticlePiece(Component.text("A"), -0.2, 0, 0),
        new ParticlePiece(Component.text("B"), 0.2, 0, 0)));
```

- Направление `OUTWARD` у такого эффекта - от центра запуска, то есть буквы разлетаются от середины слова.
- Для бесшовного перехода у эффекта: `billboard: "FIXED"`, `animation.rotation: 0`, без `fadeIn`; без `colors` -
  буквы сохраняют цвет слова (с `colors` / `animation.color` они перекрашиваются).
- Позиции букв считаются по ширинам шрифта Minecraft по умолчанию (латиница точно, остальное ≈ 6 px): со своим
  шрифтом из ресурспака буквы могут немного сместиться.

## Как частицы попадают к игрокам

По умолчанию (`particles.packets: true` в `config.jmc`) частицы - **пакеты без сущностей на сервере**: их нет ни в
чанках, ни в трекере, ни в тике мира, сервер только считает движение и шлёт клиентам те же пакеты, что и для
Display-сущности. Пакеты тика уходят игроку одной связкой. На замере (Paper 1.21.11, async-profiler, 1000 живых
частиц, 10 новых за тик, один игрок рядом) время тика сервера: 6,0 → 2,75 мс без коллизий и 7,6 → 3,3 мс с
коллизиями - трекер и тик мира почти перестают тратить время, остаётся расчёт самих частиц.

- Кто видит: для `viewers: "owner"` - владелец, если он в том же мире; для `"all"` - игроки мира не дальше
  `particles.viewDistance` блоков (по умолчанию 96) от точки запуска. Список пересчитывается раз в полсекунды:
  подошедший игрок получает частицы в текущем виде, отошедший - их удаление. Пока зрителей нет, новые частицы
  не появляются (как у сущностей в незагруженных чанках).
- Пакеты используют внутренние классы сервера Paper 1.21.11. На другой версии сервера плагин пишет предупреждение
  и сам возвращается к сущностям; `packets: false` - сущности всегда. Режим видно в `/dlib particle list`.
- Слово `TextShatter` до распада - обычная сущность (одна на запуск).
- **Отдельный поток** (`particles.async: true`, по умолчанию): частицы эффектов без коллизий (`motion.collide: false`)
  движутся и анимируются в потоке «DisplayLib Particles» - им не нужен мир. Основной поток только создаёт частицы и
  решает, кому их показывать, а пакеты потока отправляет в начале следующего тика (так кадры доходят до клиента ровно
  раз в тик). Эффекты с коллизиями читают блоки мира и всегда считаются в основном потоке. Если поток не успевает
  за тиком сервера, его тик пропускается (частицы замедляются, как при лаге) и в консоли одно предупреждение в минуту.

## Ограничения

- Одновременно живёт не больше `particles.maxAlive` частиц на сервер (`config.jmc`, по умолчанию 1500); лишние не появляются, в консоли одно предупреждение.
- Частицы не сохраняются в мир: при перезапуске они исчезают (в режиме сущностей - и при выгрузке чанка).
- Внутри кадра клиент ведёт частицу по прямой с постоянной скоростью; сервер подбирает кадры так, чтобы скорость
  внутри кадра отличалась от средней не больше чем на 12%, а путь отходил от прямой не дальше 0.02 блока.
- Вращение - в плоскости частицы (вокруг её оси Z); за один кадр - меньше 180°, при быстром `spin` кадры учащаются сами.
- Размер, поворот и цвет - своими кадрами: сервер берёт самый длинный кадр, на котором прямая клиента отходит от
  настоящего размера не больше чем на 3% и от цвета не больше чем на 5/255 по каналу. Линейный размер без кривой цвета -
  один кадр на всю жизнь; `easing`, `fadeIn`, градиенты и кривые прозрачности дробят жизнь ровно настолько, насколько нужно.
